Paper trading: does the risk screen actually work?

Simulated $10,000 bankroll, $250 per position, zero real funds and no key. Strategy: each refresh, mark every open position to its latest price, then open a new position in anything from get_new_pools (all three chains) that doesn't get flagged "high" risk. This isn't wallet-copying — GeckoTerminal has no per-wallet trade history to follow — it's a direct test of whether the rug screen built above is worth anything, run against real pools instead of backtested on cherry-picked ones.

Built from live calls through get_trending_pools, get_new_pools, get_pool_risk, and find_early_wallets against GeckoTerminal's public API — nothing on this page was typed in by hand. One real limitation surfaced during the build: the trades endpoint returns a recent window, not full pool history, so find_early_wallets only means "earliest since launch" on pools young enough that the window covers their whole life (like Tomagari above) — on an 8-day-old pool like LAYOOO it would mean "earliest in the last few minutes." The tool description now says this explicitly.

The paper-trading ledger is paper-trade.js, run manually and persisted to paper-ledger.json in the project folder — this page can't poll GeckoTerminal itself (published Artifacts can't fetch arbitrary external APIs, and the runtime's live-data bridge only reaches claude.ai connectors, not a local MCP server), so "refresh" means asking for one, not a timer running unattended.
